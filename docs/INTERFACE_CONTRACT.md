# 软硬件接口契约（触觉夹爪）

- **状态：PROPOSED v0.1（未生效、未实现、未联调）**
- **唯一约定路径：`docs/INTERFACE_CONTRACT.md`**
- 日期：2026-11-12
- 责任方：软件组 + 硬件组共同维护
- 本文件在 S0 仅建立占位草案；**不实现**传感器通信协议、解析器、数据模型或控制算法。

## 1. 目的与约束

本文件约定后续软件组与硬件组之间的触觉采集、控制命令、状态、错误与时间信息接口。任何字段在双方书面确认前均视为 **UNKNOWN / 待确认**，不得写成已验证事实，也不得据此启用真实运动。

当前已知事实：

- 旧 ESP32（NodeMCU ESP-32S V1.1，GPIO23，50 Hz，16-bit）稳定固件 `gripper-control-bench-0.9b24.0` 保留为回退。
- ESP32-S3（YD-ESP32-S3 N16R8，GPIO4，50 Hz，14-bit）固件 `gripper-control-s3-0.9b26.0` 已由用户报告真实机械开合 PASS；精确位置误差与长期稳定性 UNKNOWN。
- 硬件组 Stage H1 目标为单侧 **6×6 触觉矩阵、36 个感测单元、三颗 ADS1220、旧 ESP32 采集**。
- 三颗 ADS1220 **不能直接提供 36 路独立模拟输入**；实际扫描/复用方案仍待硬件组确认。
- 现有 `docs/SENSOR_CONTRACT.md` 是 Stage 0 的 4×4/16 通道 row-major 草案，保留为历史资料；不能直接作为 6×6/36 单元的实现依据。

## 4. 未来接口原则（不是已达成协议）

在双方确认前，以下只作为设计审查原则，不构成字段定义：

- 显式协议版本；不兼容变更必须提升版本并保留旧版本处理策略。
- 帧有界，超长/截断/未知字段必须可拒绝；不能静默补默认值。
- 原始值与单位分离；不得把 ADC 计数、目标脉宽或模拟值当作实测角度/开度/夹持力。
- 通道有效性必须显式表达；无效通道不得按“无接触”的零值处理。
- 帧序号、MCU 时间戳与主机接收时间戳分别记录；不同时钟域不得直接相减推断延迟。
- 通信错误、超时、重复、乱序、过期帧必须有可记录的原因；错误不得触发继续闭合。
- 真实、模拟、混合数据严格标记；接口本身不得把模拟结果标为真实。
- 任何新字段先在本文件登记为 PROPOSED，再实现；实现后仍需真实联调证据才能改为 CONFIRMED。

## 5. 变更流程

1. 任一方在本文件提出变更（字段、语义、版本、待确认项）。
2. 双方评审并明确仍为 UNKNOWN 的部分；不得把未验证假设写成事实。
3. 更新状态与日期；重大不兼容变更提升版本号。
4. 经审查后合入 `main`；两个功能分支同步该共享基线。
5. 涉及真实硬件的行为变更，仍须单独的接线/上电/烧录/运动授权。
