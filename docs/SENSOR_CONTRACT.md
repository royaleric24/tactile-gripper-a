# C → A 传感数据与 A 组命令日志约定

版本：Stage 0 草案，2026-11-11。字段名称、材料枚举、16 通道及 row-major 顺序由用户提供；以下类型、校验和日志语义建议是 A 组设计草案，尚未获 C 组确认，也未实现或用于实机。

## 已确认的 sensor_frame 结构

| 字段 | 已确认含义 | 草案类型 / 仍待确认 |
|---|---|---|
| timestamp_ms | 毫秒时间戳 | 建议整数；时钟原点、采样时刻或发送时刻、跨设备同步 UNKNOWN |
| material | FABRIC 或 SILICONE | 字符串枚举；必须保留来源 |
| frame_id | 帧标识 | 建议非负整数；重启重置、回绕、会话唯一性 UNKNOWN |
| channels | 16 个数值 | 建议长度 16 的有限数值数组；ADC/电阻/其他量、单位、范围、标定 UNKNOWN |
| valid_mask | 16 个有效性标记 | 建议长度 16 的布尔数组；线上使用布尔或 0/1、失效判断规则待确认 |
| contact_score | 接触评分 | 建议有限数值；算法、单位、范围、材料差异和阈值 UNKNOWN |
| valid | 帧有效性 | 建议布尔；与 valid_mask / quality_flag 的关系 UNKNOWN |
| quality_flag | 质量标记 | 数据类型、枚举和异常含义 UNKNOWN，不能自创为已达成协议 |

通道为行优先（row-major），即一行从左到右读完，再读下一行：

| 行 | 四个通道位置 |
|---|---|
| r0 | 0=r0c0，1=r0c1，2=r0c2，3=r0c3 |
| r1 | 4=r1c0，5=r1c1，6=r1c2，7=r1c3 |
| r2 | 8=r2c0，9=r2c1，10=r2c2，11=r2c3 |
| r3 | 12=r3c0，13=r3c1，14=r3c2，15=r3c3 |

索引公式为 `index = 4 * row + column`，valid_mask 与 channels 同序。实体传感器的 r0c0 方向仍需 C 组通过接线图或照片确认。

## 尚待 C 组确认的传输与校验

- 传输介质和端点（串口/网络/文件等）、编码、消息边界、校验机制、采样率、最大延迟均为 UNKNOWN；本轮不指定波特率或默认端口。
- 确认通道数值的物理意义、单位、基线/标定方法、坏通道占位值和评分算法。无效通道不能作为“无接触”的零值依据。
- 确认 valid_mask、valid、quality_flag 的优先关系、部分有效帧是否可用，以及 FABRIC / SILICONE 是否需要独立阈值。
- 明确重复、乱序、丢帧、重启、时钟同步与过期检测规则；不能直接相减不同时钟域的时间戳来计算延迟。
- 建议未来保存 A 组接收时刻及单调时钟，用于检测“多久未收到数据”；阈值必须另行确定。

建议的后续软件行为：缺字段、长度错误、非法枚举、非有限数值、未知质量标记或过期帧不得触发进一步闭合，并记录原因。设备的停止/保持/释放动作必须依据已确认协议另行设计；拒收数据本身不保证正在运动的设备已停下。本轮没有运行此逻辑。

## A 组后续命令日志

以下字段由用户要求预留，尚无实际命令记录：

| 字段 | 记录约束 / 待确认项 |
|---|---|
| timestamp_ms | 记录命令事件时刻；具体时钟原点待定，并注明与传感器时间戳的关系 |
| frame_id | 关联触发帧；无帧的人工/安全事件建议留空并说明，不伪造帧号 |
| mode | 状态/模式名称；状态机及枚举未实现 |
| target_angle_deg 或 target_opening | 按已确认控制模式使用；角度为目标角度，开度单位、参考零点及正方向 UNKNOWN；停止等无目标事件可留空，不填 0 代替 |
| command_source | 触觉、人工或安全逻辑等来源；枚举待定 |
| executed | 草案三态 true / false / unknown（CSV 可约定 UNKNOWN）；true 仅在有已定义的设备执行证据时使用；写串口成功或普通收包 ACK 不等于执行完成；模拟成功不得表示真实硬件执行 |
| safety_reason | 拦截、停止、无效帧、限位或其他安全原因；正常值约定待定 |

如保留目标角度和目标开度两个列，必须注明本次使用哪一个、另一列留空；不能凭空把设备原始计数换算为度或毫米。

建议以后另加 `command_id`、`trial_id`、`run_kind`、发送/确认状态、原始响应引用、实测值及其采样时刻/来源；这些扩展不是用户已给定的传感协议。实际角度/位置单独记录；没有反馈就未知，绝不复制目标值。

## 真实与模拟证据分离

- 本轮仅有 `HOST_ENUMERATION` 主机观察：不是传感数据、不是控制测试。
- 后续真实试验放在 `data/real/`、`logs/real/`、`videos/real/`；模拟数据与日志放在各自的 `simulation/` 目录。
- 每次运行另存清单，标注传感器来源、控制器是真实还是模拟、时间约定和文件关联。真实传感器配模拟执行器、或模拟输入配真实执行器均标为混合测试，不计入 5 次真实闭环 Trial。
- 原始数据、目标命令、设备回复和独立测量分别保留。`contact_score` 是接触评分；电阻不是力，未经独立标定不得声称测得夹持力或摩擦力。

没有提供示例 sensor_frame 或 Trial 记录，避免将草案数值误认为真实采样。

## Stage 0.5 补充：JSON Lines 提议及目录约定

2026-11-11：JSON Lines 是 A 组拟议传输格式，尚未经 C 组联调确认；现有必需字段、FABRIC/SILICONE 与 row-major 顺序不变。C 组是否实际提供 16 通道仍需验证。建议 UTF-8、每行一个对象并以换行结束；消息大小和处理时间设上限，具体上限待配置。传输介质、时钟、数值单位、质量枚举、坏通道处理及阈值仍 UNKNOWN，不新增假定协议数值。

自 Stage 0.5 起新增模拟输出改用 data/simulated/、logs/simulated/；此前段落所述 simulation/ 仅为 Stage 0 旧占位目录，原样保留且不再新增运行产物。实际与混合测试的分类规则不变。详见 [架构设计](ARCHITECTURE.md)。

## Stage 0.7 离线校验实现

新增 sensor.py 仅实现保守的离线配置：16 个有限数值、16 个全 true 的布尔有效位、valid=true、允许列表中的字符串质量标记；拒绝坏帧、NaN、重复 JSON 键、超长或未以换行结束的完整消息。SIM_OK 仅是测试质量标记，不是 C 组协议。流式分包/粘包缓冲尚未实现；调用者必须提供完整一行。协议未与 C 组确认。

状态机检查本地接收超时、帧号递增和源时间不倒退，不把不同时钟域直接相减；尚不保证识别传输链路中延迟积压但持续到达的旧帧，真实联调前需确定会话、时钟与新鲜度方案。
