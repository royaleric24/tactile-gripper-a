# Stage 0.5 软件架构与验证计划（设计，尚未实现）

日期：2026-11-11。目标是先实现真实触觉触发的有限步进闭合、停止与人工允许的释放，再考虑水杯自适应抓取。这里没有固件、串口入口或运动代码，不代表已有停止能力。

## 技术选择

| 层 | 推荐与理由 | 限制 / 备选 |
|---|---|---|
| Mac | Python + pyserial；Python 负责验证、状态机、日志，串口库只承担字节收发，便于独立测试 | uv 管理环境与锁文件；本轮不安装或打开串口 |
| ESP32 | Arduino-ESP32 官方稳定版；对一个舵机、串口协议和小状态机，工程配置工作较少，适合本次 48 小时交付 | 这是项目工程判断；芯片/板型确认后选支持它的稳定版本并锁定，不猜 FQBN 或 Flash 参数 |
| ESP-IDF | 可作后续需要更细任务/驱动控制时的备选 | 官方框架包含工具链、CMake/Ninja 等；当前不同时维护两套固件以免增加联调成本 |
| 舵机信号 | LEDC 生成 PWM，后续仅在确认该舵机接受相应信号后使用 | PWM 是周期脉冲信号，不是供电；频率、脉宽、电平和 GPIO 全部 UNKNOWN，不给通用默认值 |
| 传感器传输 | 建议 JSON Lines：UTF-8，每行一个 JSON 对象，以换行分帧，方便查看与记录 | 是 A 组提议，未与 C 组确认；传输介质也未定。限制单帧字节数和处理时间，保留原始输入 |
| 闭环 | 有限状态机 + 一次一个有限步进 + 新帧再决策；不做连续盲扫 | 步幅、累计行程、速率、时限、迟滞和阈值待确认；尚不承诺力控或实测角度闭环 |

依据：pySerial 支持读写超时，但给 Serial 构造器传端口会立即打开；打开端口可能引起 RTS/DTR 跳变，不能归类为无影响的只读检查。[pySerial API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html)

Espressif 提供稳定版和开发版安装源；后续用稳定版。[Arduino-ESP32 安装](https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html) LEDC 可生成 PWM；3.x API 使用 `ledcAttach`，不能直接照搬 2.x 的 `ledcSetup` / `ledcAttachPin`。[LEDC](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/ledc.html)、[迁移说明](https://docs.espressif.com/projects/arduino-esp32/en/latest/migration_guides/2.x_to_3.0.html)

ESP-IDF 的工程依赖见[官方入门](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/get-started/index.html)。JSON Lines 格式依据见[格式说明](https://jsonlines.org/)。这些通用资料不证明当前板型、GPIO 或舵机兼容性；不得直接执行文档中的上传、复位或串口示例。

## 模块边界与目录

```text

Mac transport/显式串口会话 ← 回复 ← ESP32 协议、限幅、独立超时 → LEDC
      ↓                            ↓
    logging/原始帧、决策、命令、回复、异常、时间与视频关联
```

- `src/gripper_a/` 预留 `sensor`、`protocol`、`state_machine`、`safety`、`transport`、`logging`；本轮未创建实现。
- `firmware/` 预留 Arduino-ESP32 固件；`tests/` 后续放纯软件测试和内存中的假传输端，禁止测试默认访问 `/dev/*`。
- `config/control.template.json` 是不能启用硬件的设计模板，全部实机控制参数为 null，`hardware_enabled=false`。没有运行时加载器；这不是已实现的软件安全保证。
- 新模拟产物统一在 `data/simulated/`、`logs/simulated/`；旧 `simulation/` 目录保留，避免破坏 Stage 0。真实产物在 `data/real/`、`logs/real/`、`videos/real/`。
- 后续先用 uv 建立 `.venv`、依赖清单和锁文件；本轮不重新初始化项目、不安装工具链，不生成虚构锁版本。

## 主机与固件的职责

以下接口是未来设计，不是现有板载固件已支持的命令。

主机：`SensorSource` 提供帧；`FrameValidator` 输出有效性与拒绝原因；`Controller.step(frame, monotonic_time)` 仅返回决策；`Transport` 在明确选择硬件并获准后才连接；`RunRecorder` 记录来源、会话、帧与命令。模拟适配器不导入/打开 pyserial。

拟议命令语义：HELLO/STATUS（能力）、ARM（显式授权）、SET_TARGET（有限目标）、STOP（撤销闭合队列并进入锁定状态）、RELEASE（独立允许的释放目标）。命令带版本、会话、command_id、关联 frame_id；回复区分 ACCEPTED / REJECTED / OUTPUT_SET，后者只表示设定 PWM，不代表到位。最终编码、参数、波特率尚未约定，禁止向当前设备发送这些词作为试探。

主机限制：一次至多一个未确认目标；命令与反馈超时；只有新鲜、有效且未消费的传感帧才能触发下一步。绝对目标而非可重放的无限增量；重试须幂等，旧会话、重复和乱序不造成新运动。串口读取有超时，不能阻塞安全检查。

ESP32 限制：启动 DISARMED，未获准不 attach PWM；每个目标独立校验范围、与上一目标的最大差、累计闭合量和命令时限；配置版本须与主机匹配。独立单调计时器检查通信租约，超时撤销待执行动作并锁定闭合。畸形帧不能刷新计时器，普通心跳不能无限延长旧动作，接收解析与日志不能无限阻塞超时检查。通信超时保护不等于 CPU 卡死保护；固件挂起/看门狗复位后的输出状态也需后续核实。

没有位置反馈时，只能核查“目标变化/信号输出”和外部观察，无法保证电机机械停止。STOP 保持最后 PWM 可能仍向最后目标运动；停止 PWM 可能掉落负载。现场确认适合的策略并测量实际停止表现之前，不宣称安全停止。人工断电路径独立确认，软件 STOP 不称为硬件急停。

## 状态与故障路径

| 状态 | 允许的行为 / 转移条件 |
|---|---|
| DISARMED | 启动/复位入口；无 PWM；仅允许识别和状态处理，显式许可与完整配置后才能 ARM |
| READY | 等待经过允许的试验开始和有效新帧，不自动闭合 |
| CLOSING_STEP | 一次有限目标；在边界内执行，等待回复和新帧；不积压后续闭合 |
| CONTACT_STOP | 达接触条件后撤销闭合，执行已验证 STOP 策略；不把接触评分叫夹持力 |
| RELEASING | 需独立允许的释放意图及负载支撑；按已验证释放目标执行 |
| FAULT | 无效/过期帧、失联、回复超时、超界或协议错；禁止继续夹紧，撤销队列，尝试 STOP 并依赖板端独立保护；无自动恢复 |

所有活动状态收到 STOP 均优先撤销闭合；传感无效不能当作“无接触”而继续夹紧。故障恢复需排除原因、确认当前机械状态并重新授权。未知位置不得假设为 0° 或最后目标。

## 后续验证计划：仅设计，未执行

以下顺序是硬件验收依赖；第 6 项软件测试应在第 3 项运动前提前完成，以尽早验证逻辑。所有固件写入与运动须另行获得用户对具体步骤的明确许可。

| 项 | 验证内容与通过依据 | 类别 / 用户亲自执行的动作 |
|---|---|---|
| 1 | 确认舵机准确型号、三线引脚、工作电压、堵转电流、PWM 参数、信号兼容性、板型/GPIO、安全行程、固定和人工断电方式；记录官方来源与照片 | 硬件确认；用户提供标签并由具备能力的现场人员核对独立供电、接线和固定，不以颜色或 180° 推导 |
| 2 | 先建立 USB 节点与开发板映射；经许可上传仅通信且无 PWM 的测试固件，验证有 ID 的请求/回复、错帧拒绝、重启后 DISARMED | 硬件确认；用户保持舵机完全隔离、确认供电与板型并批准写入/开串口；本轮不执行 |
| 3 | 确认第 1 项且软件检查通过后，用独立电源在保守安全范围验证单次有限位置；检查启动不动作和无异常发热/堵转，异常立即按已确认方式停止 | 实机运动；用户接线、固定、看护，明确批准每个操作，必要时亲自断电；不自动居中/扫全行程 |
| 4 | 选择安全范围内三个目标，外部观察/测量重复性；分别检查 STOP、失联、复位、超时的真实效果与停止延迟 | 实机运动；用户确认三点与停止方案并现场处置，记录保持/掉落风险；目标不冒充测量值 |
| 5 | Python 发出同样的受限目标，验证命令关联、拒绝超界、读写超时及主机中断后的板端保护 | 软件 + 实机；用户批准运动并看护，故障注入先确保环境可安全停止 |
| 6 | 内存假传输测试无效帧/长度/NaN、分包粘包、重复乱序、假时钟超时、接触停止、限幅、STOP 优先、无自动重连恢复、无真实端口访问 | 纯软件；可由助手离线执行；输出只标 SIMULATED，此轮仅列计划 |
| 7 | C 组确认 JSONL 与时钟/单位/质量定义；先只收真实传感器帧并核对 16 通道方向，再在前述门槛满足后启用闭环 | 联调；用户协调真实传感器触碰与接线，控制运动部分另行授权；更新 SENSOR_CONTRACT |
| 8 | 至少五次真实闭环 Trial，每次验证真实触觉触发闭合/停止及允许的释放，失败也记录；建立帧—命令—回复—视频链 | 实机；用户布置低风险物体、看护和拍视频；水杯/液体场景另评估，不作为首次动作 |

每次真实 Trial 保存 trial_id、sensor_source、actuator_source、配置快照、软件/固件版本、原始传感数据、命令/回复、状态变更、时间约定及视频文件/时间对应。必须 sensor_source=REAL 且 actuator_source=REAL 才可计为真实闭环；计数不等于全部成功，报告分别列尝试数、通过数、中断及失败原因。

软件测试不能验证电源容量、真实引脚、限位、夹持力、机械停止或保持能力；这些必须用资料与获准的现场验证确认。
