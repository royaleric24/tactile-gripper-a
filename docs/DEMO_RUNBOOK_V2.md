## 开始前：一次性确认现场

- 固定当前指定的杯子、夹持高度、两片 FSR 的受力位置；杯底布置托盘，避免杯子落下和水碰到电路/USB。
- 两个 USB 串口逐个插拔识别设备身份，不能把旧 ESP32 传感端误作 ESP32-S3 控制端；确认采集板与舵机的供电分开。
- 先使用 MANUAL 复测 `1300 μs` 的状态，记录杯体侧面照片/参考宽度；`1270 μs` 已有形变观察，先不作为默认目标。
- 设定已实测的夹持范围、PWM 每次变化的合理幅度、命令间隔、数据超时、失联后行为。**具体数值以现场结果为准，文档不编造一个通用限位。**

## 演示顺序

1. Dashboard 连 LIVE sensor，出现 FSR_A/FSR_B 原始趋势和当前值；如有 12 电极数据则显示电压列表并标明 `mapping_status`（当前 PENDING_REAL_WIRING、validated=false），**不显示 36 点矩阵热图**。
2. 创建 Trial，记录杯型、PWM 起点、软件/固件版本。Start video。
3. 在 MANUAL 抓住空杯，等待 FSR 稳定并记录基线；确认不会持续挤压杯壁。
4. 切换 AUTO；手动缓慢加水并观察接触状态/PWM 变化。没有足够滑移风险证据时规则可选择 HOLD，不要求为了演示故意夹紧。
5. 有效触发时保留 FSR 原始波形、决策原因、目标 PWM、ACK 与杯子变化；若 AUTO 没触发要诚实记下。
6. 停止实验，保存 `frames.jsonl`、`events.jsonl`、`metadata.json`、CSV、视频；用 REPLAY 复现。

## 控制策略概念（具体实现留给软件组）

```text
取得最新有效的 FSR_A/FSR_B
    ↓
是否为 LIVE 且新鲜、两路传感器质量合格、S3 在线？
    否：禁止新的自动夹紧，显示 HOLD/FAULT，等待人工处理
    是：检查 PWM 指令是否完成、是否超过动作频率上限
         ↓
若接触过强：适量放松（不能超过已验松开边界）
若接触不足，且实际观察已证明该信号对应滑移风险：适量夹紧（不能接近已知形变风险区）
其他：保持当前 PWM
         ↓
记录原因、命令 ID、ACK、传感器帧序号；下一帧再评估
```

不要把 FSR 数值直接命名为摩擦力、牛顿或夹爪角度。软件 STOP 不是机械急停：在此前确认它会保持、断输出还是松开之前，不要用它代替托盘/断电手段。

## 失败时的降级路径

- **FSR 有效、12 电极不可用**：保持 `FSR_ONLY`，仍可做真实 AUTO；UI 显示「电极未校准/映射未填」。
- **AUTO 信号不足或误动作**：切 REAL_ASSISTED_DEMO，操作员用 MANUAL 调节，仍真实记录传感器与动作；不宣称自主闭环。
- **真实控制暂不可用**：独立演示传感器 LIVE + Dashboard SIMULATION/REPLAY，清楚说明动作来自何种数据源。
- **两路 FSR 都无效**：不进入 AUTO；先修复测量链路，不拿伪造波形替代。

## 快速评估表

| 检查项 | 记录方法 |
|---|---|
| 真实传感器 | 设备 ID、boot_id、串口、固件、有效原始帧 |
| 真实控制 | S3 ID、请求/ACK、目标 PWM、视频中可见的实际开合 |
| 水杯是否变形 | 同角度照片/刻度或现场观察，注明主观判断 |
| 加水是否触发反馈 | 加水标记时间、FSR 变化、决策及 PWM 时间线 |
| 是否滑落 | 有/无；出现时记录开始时刻与恢复动作 |
| 成果级别 | A=REAL_AUTO；B=REAL_ASSISTED；C=REAL_SENSING_PLUS_SIMULATION |
