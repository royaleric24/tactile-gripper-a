## 3. GPIO23、电源与信号审查

GPIO23 是 ESP32 的信号 I/O，当前以板载约3.3V逻辑域讨论，不是舵机动力电源，也不按5V容忍输入使用；驱动/输入允许条件以 S1 的供电和 DC 表为准。没有测量实际板 VDD/输出高电平；兼容性需要“GPIO 输出保证值在实际负载下”与“PM10D 输入 VIH/VIL、输入电流/上拉来源”同时核实。不能用“舵机5V供电”推导“信号必须5V”，也不能推导“3.3V必然够用”。若需缓冲/电平转换，先核定方向、输入阈值、掉电隔离和默认态再选型，不能往 ESP32 信号端灌5V。

官方 GPIO23 表：At Reset `oe=0, ie=0`，After Reset `oe=0, ie=1`，未标该脚弱上拉/下拉；默认不驱动输出，并非主动低电平。**高阻是输出驱动状态，线上的实际电压可受外部电路、漏电、探头和耦合影响。** 不把官方芯片复位默认当成整块板上电到应用运行全过程已测结果。

板上 P23 的实际孔位：参考表37/P23、38/GND可帮助核对，但不能直接按“第几个孔”盲数；本板 USB-C、丝印方向/板版本/邻近 GND 必须用正反面照片和适用原理图确认。本轮没有实物照片，因此不指定“左上/右下第几针”。

PM10D 三线分别应按厂家定义确认电源正、地、信号；用户描述黑/红/白不构成引脚证据。接头正反方向、插针顺序、延长线是否交叉均需确认。

独立供电下，单端信号需要共同参考地；这是候选电路要求，不表示现在可以把任意两个电源负极/接地端直接相连。需核实 USB 电源、Mac、测量仪器的地/隔离关系，设计信号地回路，避免电机回流经 GPIO 参考线或 Mac USB 细地线。两路正电源不得随意并接；舵机断电时 GPIO 信号是否经保护二极管回灌、ESP32断电时是否被舵机信号上拉反供，也需输入电路资料确认。

独立5V USB电源：额定电流、瞬态能力、线缆压降、连接器/开关容量、短路/过流/热保护未知。要求提供完整供电链（适配器/移动电源→USB线→转接/开关→舵机），不能只看“5V”字样。所需电流须依据 PM10D 的启动/运行/堵转资料及后续受控测试确定，本轮不编造安培值。不要人为堵转测电流，不把USB充电协议标称或板5V针脚当合格动力输出。3V3不满足用户提供的4–6V范围；10 kg·cm不等于连续安全扭矩。

## 5. 实际固件及 Python 安全逻辑审查

| 检查 | 实际实现及结论 |
|---|---|
| DISARMED / 启动顺序 | 全局 attached=false；setup 先 Serial，再配置 Limits、构造 DISARMED 核心和 boot_id。无 GPIO23 pinMode/digitalWrite，也无 LEDC attach。故输出不是软件强制低，而是未驱动 |
| 硬件 false | SafetyCore::Limits.valid() 与 LedcOutput::set() 双重拒绝；当前编译常量false、校准false、范围0占位。没有远程解锁/标定路径 |
| ARM | 会话/递增序号有效、DISARMED、完整校准/使能才能 ARMED；ARM自身不输出 |
| SET | 必须 ARMED/ACTIVE；校核范围、首目标、相邻和累计幅度、速率；之后 output.set 再检查编译门槛，attach后写换算duty，检查API和读回 |
| STOP | 请求 off；未attached直接返回，不调用PWM；FAULT中保持故障，不恢复旧目标 |
| DISARM | 请求 off，成功进入DISARMED、清目标；失败FAULT/UNKNOWN；这不等于机械保持 |
| FAULT | 尝试off并保存原因；输出API错误/关闭失败标UNKNOWN，无自动恢复。实现可疑点见下表，不扩大到物理保证 |
| 失联/超时 | loop及命令入口tick；仅ARMED/ACTIVE检查1000ms通信期限；ACTIVE另有2000ms输出租约，心跳不续租。DISARMED下不因静默进入FAULT，这是预期，不证明活动超时分支实测 |
| 重启 | BSS/对象默认重建DISARMED/不attach，新boot_id。既有实测确认新启动锁定；ROM/引导/电源瞬态仍须物理测量 |
| 额外输出路径 | 项目控制固件仅适配器set路径attach/write、off路径写0/detach；没有其它GPIO23输出调用。符号可达性不是外部电气验证 |
| 首次动作限制 | 首脉宽、步幅/累计变化量、100ms间隔、期限及显式许可都有设计；当前均无法解锁。首目标约束相对配置，不知道真实轴角/开度，不能保证第一次“跳向首目标”幅度很小 |

### 发现的问题及最小建议（只记录，不修改代码）

1. **未来关闭失败的 UNKNOWN 可被过早清除。** `LedcOutput::off()` 若写0失败但detach成功，attached已false且off返回false；再DISARM时off直接true，核心会清UNKNOWN，没有独立状态验证。建议让输出适配器保留故障/不确定锁存，关闭状态未经明确验证不清；同时按适用策略避免宣称外部电压被确认。当前锁定构建未attach，不触发该活动路径。
2. **未来首次attach与写duty并非原子。** 当前先attach再写目标；前后初始电平和边沿未经测量，不能保证无瞬态。建议先在无舵机台架测启动/attach/故障波形，再决定低态初始化、硬件信号门控或独立保护；不要本轮修改。
3. **主机本地参数拒绝不立即撤销已有输出。** `reject()`只记日志抛异常，未发送STOP；活动脉冲可持续到设备通信期限/输出租约。建议后续约定异常收敛策略并测试；不要简单假定STOP/断PWM对负载安全。
4. **CPU阻塞、硬复位、独立电源异常不由Python租约完整覆盖。** 发送空间检查/有界解析有帮助，但无独立物理断电闭锁。建议后续验证实际最大停止延迟、CPU看门狗与外部安全措施；当前不得声称失联硬件安全已通过。

已通过的锁定固件和真实日志保留，不做控制补丁。问题1–4需在获准准备活动输出的版本审查中解决/明确接受，不构成本轮偷偷修改的理由。

## 7. C2：独立PWM台架验证方案（仅设计，NOT_TESTED）

当前生产锁定固件不能产生PWM，**不临时改硬件false或伪填安全限位来驱动它**。后续另建无舵机专用、固定信号且有最大运行时间的测量固件，源代码、编译、上传、GPIO启用分别审查/授权。测量固件不得复用为机械运动控制器；固件切换前保留现有构建哈希。

拟议纯电气信号：50Hz / 20ms周期、1500μs高脉宽、约7.5%占空比、3.3V逻辑域；这是**仪器目标，不是PM10D安全起点**。仅固定这一值、不扫500–2500μs；一次最多2秒的候选测量窗口，之后自动禁用。未获批准前不生成/上传/运行该固件。

用上升沿到上升沿测周期T，下降沿到同一周期上升沿差测高脉宽t，f=1/T、D=t/T。至少记录多周期的最小/最大/均值和抖动；模拟示波器查高低电平、上升下降沿、过冲/欠冲、启动首脉冲、停止末脉冲，不能只用软件duty计算。

候选台架验收值（方案值，待仪器能力与具体测试代码批准后冻结）：稳态频率50Hz±1%，高脉宽1500μs±10μs，无额外脉冲列，幅值满足最终核准的输出/仪器及接收器电气条件。未有PM10D阈值时只能判信号发生器符合目标，不能判舵机接口兼容。

期望：启动/未允许期间无PWM；显式测量窗口内才有信号；STOP、2秒到期、通信故障后有界退出，拟要求进入明确低态而非假定detach=低；复位期间可能高阻，须观测并考虑未来硬件门控。具体低态初始化/保护方案未实现，不能当当前固件的行为。记录停止延迟、是否出现截短/额外脉冲；停止时限须由测试固件审查明确并与实测比较。

失败：未启用已有周期波形、参数/幅值超验收范围、窗口到期后继续输出、重启自动恢复、异常毛刺；立即停止该台架方案并分析，不接舵机“试试看”。没有仪器则维持NOT_TESTED，借实验室仪器或请有设备人员按记录模板测量；万用表平均电压、LED、API返回、寄存器读回和串口日志不能替代波形验证。
